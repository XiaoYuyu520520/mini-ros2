# bridge\docs · 五份文档 + 验收证据

这一套文档写的不只是 `bridge/`：兼容层、SDK、Linux 侧、CI 都在里面，所以从这里开始读是对的。

| 文件 | 写什么 | 什么时候看 |
| --- | --- | --- |
| `01-architecture.md` | 架构：守护进程、图、共享内存通道、跨机编解码怎么拼起来 | 第一次读代码之前 |
| `02-running.md` | 怎么跑：每个 bat / 脚本的参数、前置条件、现场问题怎么查 | 跑不起来的时候 |
| `03-validation.md` | 验证记录：每次改动的实测输出（命令 + 结果），按证据编号排 | 想知道「这条到底验过没有」 |
| `04-gaps.md` | 缺口清单：已知问题、没验的部分、口径更正 | 接手前必读，别重复踩 |
| `05-audit.md` | 审查：独立复核能力与证据、五棵树的隔离性与并行重复性 | 想复核结论本身 |
| `validation/` | 验收产出的数据：`acceptance-report*.json`、nav2 演示报告、SLAM 地图 png | 对着报告看数字 |

约定：

* 这几份是**有日期的记录**，不是活文档。改过的结论用「**2026-09-18 更正 / 已补上**」这样的
  补记追加，不要把原来的实测输出改掉 —— 那会把「当时看到什么」抹掉。
* 每条结论都要能落到一条命令和一段输出上；引用别的文件写路径（`nav2\ros2_shim\build.py:96`），
  路径与行号过期时要一起改。
* `.md` 是 LF + UTF-8 BOM，`python tools\check_docs.py` 会查（`CR` 字节直接报错）。

`bridge/tests/fixtures/` 与 `.scratch/` 是这套文档引用的证据与基准数据，别挪：前者有
`cdr_check` 按 `manifest.tsv` 遍历，后者的引用由 `tools/find_scratch_refs.py` 校验。
